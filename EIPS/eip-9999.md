## Abstract

Every byte that lands in the [EIP-7928](./eip-7928.md) Block Access List (BAL) reserves [EIP-7623](./eip-7623.md) floor gas at the same per-byte rate as non-zero calldata (64 gas/byte). The reservation is taken at runtime, before the BAL grows, and the running total replaces the static floor in `tx.gasUsed = max(execution, floor)`. Worst-case block bytes stay bounded at `block_gas_limit / 64`, closing the BAL-driven bypass that EIP-7928 opens against EIP-7623's data floor.

## Motivation

[EIP-7623](./eip-7623.md) caps worst-case block size by charging at least 64 gas per non-zero calldata byte. [EIP-7981](./eip-7981.md) extended that to access-list entries; [EIP-8131](./eip-8131.md) extended it to [EIP-7702](./eip-7702.md) auth tuples. [EIP-7928](./eip-7928.md) introduces a new source of block bytes, the BAL, populated by runtime opcodes. None of those floor extensions cover it.

The cheapest BAL contributor is a cold `SLOAD`: 32 bytes for 2,100 gas. Combined with all-non-zero calldata, an attacker pushes intrinsic gas above the calldata floor, pays intrinsic, and gets calldata at 16 gas/byte while loading the rest of the block via `SLOAD` keys.

At a 60M gas limit:

| Attack | Worst-case block bytes |
|---|---|
| Pure calldata at floor | 0.894 MB (target) |
| EIP-8131 auth bypass | 1.067 MB |
| Cold-`SLOAD` bypass under EIP-7928 | **1.548 MB** |

`SSTORE`, address access, `CREATE`, and successful EIP-7702 delegations give further vectors. This EIP closes them with one uniform mechanism.

## Specification

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in RFC 2119 and RFC 8174.

### Constants

```
FLOOR_GAS_PER_BYTE          = 64   # rate at which any block byte is paid at the floor (EIP-7976)
BAL_BYTES_PER_ADDRESS       = 20
BAL_BYTES_PER_STORAGE_KEY   = 32
BAL_BYTES_PER_STORAGE_VALUE = 32
BAL_BYTES_PER_BALANCE       = 32
BAL_BYTES_PER_NONCE         = 8
AUTH_TUPLE_BYTES            = 101  # EIP-7702 authorization tuple size
DELEGATION_CODE_BYTES       = 23   # EIP-7702 delegation marker length
```

### Reservation helper

Clients keep an internal, per-transaction `floor_gas_used` counter on the execution environment for the duration of the transaction. It is not part of the signed transaction, RLP-encoded, gossiped, or persisted; no new transaction field or type is introduced. The counter is seeded with the static floor (below).

```
def reserve_floor(tx_env, num_bytes):
    new_floor = tx_env.floor_gas_used + num_bytes * FLOOR_GAS_PER_BYTE
    if new_floor > tx_env.gas_limit:    # tx_env.gas_limit = tx.gas
        raise OutOfGasError
    tx_env.floor_gas_used = new_floor
```

`reserve_floor` MUST be called BEFORE the matching BAL insertion or state mutation. An `OutOfGasError` aborts the operation before any unpaid BAL byte exists.

### Static floor seed

```
auth_bytes = AUTH_TUPLE_BYTES                  # 101: tx-blob tuple (EIP-8131)
           + BAL_BYTES_PER_ADDRESS             #  20: authority address
           + DELEGATION_CODE_BYTES             #  23: delegation marker
           + BAL_BYTES_PER_NONCE               #   8: authority nonce

static_floor = TX_BASE + FLOOR_GAS_PER_BYTE * (
      len(calldata)                                                  # EIP-7976
    + BAL_BYTES_PER_ADDRESS     * num_access_list_addresses          # EIP-7981
    + BAL_BYTES_PER_STORAGE_KEY * num_access_list_storage_keys       # EIP-7981
    + auth_bytes                * num_authorizations                 # EIP-8131 + this EIP
)
```

`tx_env.floor_gas_used` is initialised to `static_floor` at the start of execution. The per-auth term covers each authorization's worst-case BAL contribution statically, so `set_delegation` (which runs before the EVM's OOG handler) never reserves at runtime.

Per-transaction accounting always adds further BAL entries that no opcode places there: sender, coinbase, and target (each with address plus the relevant balance/nonce changes); recipient balance for value transfers; contract nonce on creation; optional top-level EIP-7702 delegated target. These total at most 184 bytes, fully covered by the `TX_BASE / FLOOR_GAS_PER_BYTE = 328` bytes of headroom already in `TX_BASE`.

### Runtime reservations

| Trigger | Bytes |
|---|---|
| Cold account access (`BALANCE`, `EXT*`, `CALL*`, `SELFDESTRUCT` beneficiary, `CREATE`/`CREATE2` deployed address) | 20 |
| Cold storage access (`SLOAD`, `SSTORE`) | 32 |
| `SSTORE` whose new value differs from the current value | +32 |
| `CALL` with non-zero value to a different account | 32 |
| `SELFDESTRUCT` with non-zero balance to a different beneficiary | 32 |
| `CREATE` / `CREATE2` after the collision check (new contract's nonce) | 8 |
| `CREATE` / `CREATE2` with non-zero endowment (new contract's balance) | +32 |
| Successful `CREATE` / `CREATE2` deploy, just before `set_code` | `len(deployed_code)` |

EIP-7702 delegations are covered by the static `auth_bytes` term. `CALLCODE`, `DELEGATECALL`, and `STATICCALL` transfer no value out of the executing account and therefore take no balance reservation.

### Final charge

```
tx.gasUsed = max(execution_gas_used, tx_env.floor_gas_used)
```

Transaction validation continues to require `tx.gas >= max(intrinsic, static_floor)`.

### System transactions and withdrawals

System-contract calls (EIP-2935, EIP-4788, EIP-7002, EIP-7251) and withdrawals do NOT consume from a per-transaction floor. Their BAL bytes are absorbed by the existing EIP-7928 block-level buffer `bal_items <= block_gas_limit / ITEM_COST`.

## Rationale

### Floor side, not intrinsic side

Raising opcode intrinsic costs would penalise every user, including ones who never bypass. Charging on the floor only bites when execution is too cheap to cover the floor, which is exactly the bypass case.

A pure intrinsic surcharge also fails to cap the block at `gas_limit / 64`: for any added per-`SLOAD` cost `X`, the optimum bypass still yields `B = gas_limit / 64 + 24 · gas_limit / (2100 + X)` bytes, with the residual only vanishing as `X` grows large. Floor-side charging gives a closed bound directly.

### One per-byte rate

Pricing every BAL byte at the same `FLOOR_GAS_PER_BYTE` as non-zero calldata makes the worst case invariant to the attacker's choice: calldata, auths, storage keys, addresses, code, and balances all yield `1/64` bytes per gas at the floor. The optimum collapses to `B = gas_limit / 64`.

### Reserve before, not refund after

EIP-7928 keeps accessed addresses and storage keys in the BAL even when their call frame reverts. Reserving before the insertion guarantees every BAL byte is paid for, and an out-of-gas at the reservation aborts before the matching insertion. A refund-on-revert design would have to interact with EIP-3529 storage refunds and the existing OOG semantics; pre-reservation avoids both.

### Per-auth coverage is static

`set_delegation` runs outside the EVM's exception handler. A runtime `reserve_floor` raising `OutOfGasError` there would propagate uncaught and crash block processing. Folding the worst-case 152 bytes per auth (101 tuple + 51 BAL) into the static floor lets `set_delegation` mutate state freely: any transaction whose `tx.gas` cannot cover it has already been rejected at validation.

### `max(execution, floor)` preserved

The EIP-7623 / EIP-8131 charging shape is unchanged; only the floor side has a runtime tail. Transactions whose execution exceeds the floor pay exactly as today.

## Backwards Compatibility

A backwards-incompatible gas repricing requiring a hard fork.

The static floor gains the runtime reservation tail and the larger per-auth term (152 bytes vs EIP-8131's 101). For an authorization, the new floor charge per auth is `152 × 64 = 9,728` gas, still below the existing `AUTH_PER_EMPTY_ACCOUNT = 25,000` intrinsic per auth. The minimum `tx.gas` for a transaction therefore changes only when the floor side already dominated, i.e. for calldata-heavy or BAL-heavy transactions. A bare ETH transfer stays at `21,000`.

Wallets and `eth_estimateGas` MUST compute the new static floor (including the per-auth term) and, when tracing execution, accumulate the runtime reservations for cold accesses, value-bearing calls, and deployments alongside intrinsic gas.

## Test Cases

### Bare ETH transfer

`tx.to = recipient`, `tx.value = 1 ether`, `tx.data = b""`.

- `static_floor = TX_BASE = 21,000` gas.
- Minimum `tx.gas = 21,000`, unchanged.

### Cold `SLOAD` bypass attempt

Pre-EIP optimum at `gas_limit = 60M`: 937,500 non-zero calldata bytes plus 21,429 cold `SLOAD`s in one transaction.

- Static seed: `21,000 + 64 × 937,500 = 60,021,000`.
- Per cold `SLOAD` reservation: `32 × 64 = 2,048`.
- Cumulative floor after 21,429 `SLOAD`s: `60,021,000 + 21,429 × 2,048 ≈ 103.9M`, exceeding `gas_limit`. The transaction fails validation or hits `OutOfGasError` mid-execution.
- The largest feasible mix yields `B = gas_limit / 64 = 937,500` block bytes regardless of the calldata / `SLOAD` split.

### Cold `SSTORE` (zero → non-zero)

Single cold `SSTORE` writing a non-zero value to an empty slot.

- Reservations: `32 (key) + 32 (value) = 4,096` gas.
- Intrinsic `SSTORE` cost: 22,100. `max(intrinsic, floor) = intrinsic`. The reservation is free relative to the dominant intrinsic.

### Reverted `CALL` with value

`CALL` with `value > 0` to a recipient that reverts.

- 32-byte balance reservation is taken before `generic_call`.
- The recipient's balance change is discarded on revert (per EIP-7928); the reservation is not refunded.
- Over-reservation by 32 bytes; the bound still holds.

## Security Considerations

### Block-size bound

Per transaction, every byte the tx contributes to the block (tx blob + BAL) is paid at the floor rate via either the static seed or a runtime reservation, with implicit per-tx bytes covered by `TX_BASE`:

```
block_bytes_per_tx × FLOOR_GAS_PER_BYTE  ≤  tx_env.floor_gas_used  ≤  tx.gasUsed
```

Summing across user transactions:

```
sum(block_bytes) ≤ sum(tx.gasUsed) / 64 ≤ block_gas_limit / 64
```

System-contract and withdrawal contributions are bounded separately by the EIP-7928 block-level `ITEM_COST` buffer (~1,428 items at a 60M gas limit), sized to absorb existing system contract use.

### Reverts

Accessed addresses and storage keys persist in the BAL across reverts (per EIP-7928); balance, nonce, code, and storage-value changes from reverted frames are discarded. Reservations for discarded entries are not refunded. Safe: the implementation over-reserves, never under-reserves.

### Repeated writes to the same slot

`SSTORE` reserves another 32 bytes each time it changes the current value, even though the BAL records only one final post-value per slot per transaction. The implementation over-reserves; the bound still holds.

### Gas estimation

Wallets and `eth_estimateGas` MUST simulate `floor_gas_used` alongside intrinsic gas. Without it, estimates for floor-bound transactions are too low and submissions will be rejected at validation.
